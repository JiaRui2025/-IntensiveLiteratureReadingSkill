# 页面结构规范

目标是**以写作为目的**的精读页：读者看完不只懂内容，还能提取可复用的句子骨架与论证动作。因此三部分的顺序不可调换——先看骨架（知道作者在干什么），再看句子（知道怎么写的），最后拿工具（自己写时能调用）。

```
第一部分 · 框架      s0 阅读方式 → s1 解决什么问题 → s2 全文骨架
                    → s3 论证主线 → s4 方法论 → s4b 图版 → s5 写作动作
第二部分 · 逐段精读  part2：N 个单元 / M 句，每句四栏
第三部分 · 工具箱    t1 句式库 → t2 引用动词 → t3 hedging → t4 时态
                    → t5 连接词 → t6 自检
```

---

## s0 · 阅读方式

先给读者一个坐标系。若上一篇精读的是同类文章，**必须点明差异**，否则读者会用错误的预期读。

核心是一张表：`部分 | 内容 | 解决你的哪个问题`。第三列写「你的问题」，不写「本章内容」——前者是读者视角。

review 与 research article 的差异值得单列：

| | review | research article |
|---|---|---|
| 靠什么立论 | 重新组织已有文献 | 生产新证据 |
| 核心动作 | 分类、比较、改写范式 | 提假说、设计对照、排除竞争解释 |
| 写作训练点 | 如何综述与反驳 | 如何管理不确定性 |

---

## s1 · 这篇文章在解决什么

**三层问题，层层收紧**。这是全页最重要的设计：不要平铺「背景—问题—意义」，而是让三个问题一个比一个窄，最后窄到本文假说正好能填。

- **Q1 一个不该存在的现象**：给反差。「本该坏，却没坏」。证据要落到具体图或原句。
- **Q2 已有解释不够用**：先完整承认旧解释有效（给面子），再用 `alone` / `fully` / `only` 指出它覆盖不到的地方。**不要在这里树敌**——说「旧解释不完整」，不说「前人错了」。
- **Q3 机制空白**：精确到「有机物到底在哪儿」。这一层的问题必须能被一句话回答，且答案就是本文的假说。

每层用 `.box` 包一个 `<h4>Qn ...</h4>`，末尾加一行 `<p class="note">证据 / 原句</p>`，给出可核查的锚点。

然后给**答案的三个层次**（结构层 / 因果层 / 性能层），用一张表把「结论」和「关键证据」并置。这一设计让读者立刻明白：结论不是一句话，而是一条从结构到性能的链。

> 质量线：Q1 的现象要能用数字描述（>1200 年、0.64 wt%）；Q2 的限定词要引用原文；Q3 的空白要能对应到某张图。

## s2 · 全文骨架

一句话概括结构逻辑，然后一张表：`段落 → 在干什么 → 承担什么论证任务`。

再加**篇幅占比条**（`.bar` / `.w`）——读者对「重心在哪」的感受，往往来自篇幅而非标题。方法段占 40% 的文章，和占 15% 的文章，写法完全不同。

---

## s3 · 论证主线

用 `.chain` + `.step` 画证据链，每步三问：**做了什么 → 得到什么 → 排除了什么**。

再配一张**证据矩阵**：`主张 | 证据 | 手段 | 强度`。「强度」一列是关键——它逼作者（和你）承认：哪些结论是硬证据，哪些只是相容。

图序即论证序。如果两张图站在同一证据层级，它们大概率可以合并；如果某一层缺席，审稿人一定会问。

---

## s4 · 方法论通俗版

读者不需要会做实验，但需要知道**每个手段在回答什么问题**。每个方法一张 `.mcard`，固定三段：

1. **一句话原理**：用日常类比讲清它测什么物理量（例：纳米压痕＝用一根极细的针压进去，看它退回来多少）。
2. **在这篇里回答什么**：把它钉到某个具体主张上。
3. **怎么看结果**：给出「正常长什么样」的基准，读者才知道异常在哪。

最后用一张表区分**易混概念**（强度 vs 韧性、晶间 vs 晶内、晶格应变 vs 晶粒尺寸）。这类混淆是审稿意见的高发区。

## s4b · 图版精读

先给一段总述：这些图不是并列的，是**递进**的。用一张表列出 `图 | 证据类型 | 它回答的问题 | 对应章节`，并明确写出「图序不可调换」的理由。

每张图三层，缺一不可：

| 层 | 回答 | 写法 |
|---|---|---|
| **在证明什么** | 这张图承担哪个举证任务 | 一句话点明，再说它**不**承担什么（如「它证明韧性，不证明强度」） |
| **怎么看** | 读者的眼睛该落在哪 | 按分图字母走，给基准（「正常是锐点，弧＝介晶」），给关键数值 |
| **写作提示** | 能学走什么 | 排版逻辑、图注写法、作者如何处理不利数据 |

图注本身是**自带数据的微型结果段**——很多读者只看图和图注。所以图注必须含「是什么 + 关键数值 + 测试条件」。

收尾用一个 `.box.accent` 提炼共性（如「证据要分层，不要堆量」）。

## s5 · 写作动作清单

六条，每条一个动作 + 具体做法 + 本文对应位置。动作要**可执行**，不写「要严谨」这类空话。

再补一个**高价值专题**：如何排除竞争解释。用表对比 `竞争解释 | 排除逻辑 | 原句`，并指出两种排除逻辑的措辞差别：

- **证据不足** → `we cannot fully rule out ... but it is very unlikely`（留余地）
- **物理不可能** → `this rules out the possibility`（更强）

> 排除的力度必须匹配证据的类型。这种分寸感是审稿人最看重的。

## t1–t6 · 工具箱

- **t1 句式库**：按**写作功能**分类（定义 / 开题 / 让步 / 排除 / 对照 / 收束），不按字母。每条给模板 + 用在哪。
- **t2 引用动词与 we**：给一张表说明 `we` 只出现在「需要人承担责任」的地方；客观事实、仪器数据、前人结论都不用 we。
- **t3 Hedging 梯度**：从「确定」到「完全开放」排成 8 级，每级给措辞、用在哪、本文实例。重点讲 `might suggest` 后面为什么必须跟 `However`。
- **t4 时态规则**：数据用过去时，结论用现在时，前人工作用现在完成时。给一个反例说明改错会误读。
- **t5 连接词地图**：按功能分组，重点讲 `however` 逗号位置（句首＝大转折，句中＝小修正）。
- **t6 自检清单**：12 条，每条一个可勾选的动作。

工具箱的价值在于**可检索**：读者带着「我要写让步段」来，三十秒内能取到骨架。
